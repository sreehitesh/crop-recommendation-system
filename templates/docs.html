{{ ic.icon('target', 18) }} Project objective

Crop Recommendation System Using Machine Learning

Build a reproducible machine learning web application that recommends a crop label from seven soil and climate measurements. The project trains and compares three classifiers on a public agricultural dataset, records their measured performance, deploys the best one through a Flask API and exposes it in a dashboard that is honest about what the model can and cannot do.

Compare

Decision Tree, Random Forest and SVM tuned with cross-validation on the training split.

Measure

Accuracy, macro precision, macro recall, macro F1, per-class metrics and confusion matrices on a held-out test set.

Deploy

The selected pipeline is saved with joblib and re-used as-is for every prediction - no retraining per request.

{{ ic.icon('info', 18) }} Problem statement

Choosing a crop means matching soil fertility and expected weather to a crop's requirements. Soil test reports give N, P, K and pH; weather records give temperature, humidity and rainfall. This project shows that a supervised classifier can learn the pattern between those seven numbers and the crop label recorded for them, and can then return a consistent suggestion for a new set of measurements.

The system is a decision-support prototype. It does not predict yield, profit or crop success, and it contains no fertiliser, irrigation or disease advice.

{{ ic.icon('refresh', 18) }} Training workflow

  1. Load data/Crop_recommendation.csv and validate the schema (columns, dtypes, missing values, duplicates, class counts).
  2. Separate X (seven features, in fixed order) from y (label); the target is never used as an input.
  3. Stratified 80/20 train-test split with a fixed random seed so the split is reproducible.
  4. Tune each algorithm with 5-fold stratified cross-validation inside the training partition only, scoring macro F1.
  5. Evaluate the three tuned pipelines once each on the same held-out test set.
  6. Select the deployed model from those measured test metrics, then save the complete fitted pipeline with joblib.
  7. Write reports/metrics.json, reports/classification_report.txt and the confusion-matrix images.

{{ ic.icon('chart', 18) }} Evaluation metrics

  • Accuracy - share of correctly classified test records.
  • Macro precision - average per-crop precision; every crop counts equally regardless of frequency.
  • Macro recall - average per-crop recall.
  • Macro F1 - harmonic mean of macro precision and recall; the headline number because the classes are balanced.
  • Per-class report and confusion matrix - show which crops are confused with which.

Browser UI (HTML + CSS + JavaScript + Chart.js)
        |
        |  fetch POST /api/predict  { N, P, K, temperature, humidity, ph, rainfall }
        v
Flask backend (app.py)  ->  server-side validation (src/validate_data.py)
        |
        v
Saved scikit-learn pipeline (models/crop_pipeline.joblib)
        |
        v
Predicted crop label + optional model scores + warnings  ->  result card

Training is separate:  src/train.py  ->  models/ + reports/
  • app.py - Flask routes, JSON API, error handling, report image serving.
  • src/train.py - dataset validation, tuning, evaluation, artifact and report writing.
  • src/predict.py - loads the saved pipeline and produces predictions (also a CLI).
  • src/validate_data.py - dataset schema checks and payload validation policy.
  • src/common.py - paths, feature order and training constants shared by every module.
  • tests/ - pytest suite covering validation, prediction and the HTTP API.

{{ ic.icon('shield', 18) }} Validation policy

  • Hard rejection (400): missing field, empty value, non-numeric text, NaN or Infinity, or a value outside a physically meaningful range (humidity outside 0-100 %, pH outside 0-14, negative rainfall, and so on).
  • Accepted with warning (200): a numeric, physically possible value that lies outside the range observed in the training data. The prediction is still returned, with a warning that the model has no similar examples.
  • The dataset minimum and maximum are not treated as agricultural limits.
  • User values are never silently changed, rounded or clamped.
  • The browser performs the same checks for quick feedback, and the server re-validates every request regardless.

{{ ic.icon('alert', 18) }} Limitations and responsible use

  • The dataset has no location, soil-type, season or irrigation field, so the model cannot make regional claims.
  • Every crop class has exactly 100 records, which is unrealistic for real farm surveys and makes the task easier than field conditions.
  • Records appear partly augmented, so the model learns dataset patterns rather than measured farm outcomes.
  • Model scores are not calibrated probabilities of crop success.
  • Rainfall's accumulation period is not documented, so the interface states only "mm".
  • The output is educational decision support and should be checked against local soil tests and agricultural advice.

{{ ic.icon('refresh', 18) }} How to run the project (Windows)

:: 1. open the project folder
cd "C:\path\to\project"

:: 2. create and activate a virtual environment
python -m venv .venv
.venv\Scripts\activate

:: 3. install dependencies
pip install -r requirements.txt

:: 4. get the dataset (skip if data\Crop_recommendation.csv already exists)
python src\download_dataset.py

:: 5. train and evaluate the three models
python src\train.py

:: 6. start the web application
python app.py

Then open http://127.0.0.1:5000 in a browser and use the Crop Recommendation page. Run the automated tests with pytest -q.
